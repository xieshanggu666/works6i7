# 🏅 青春杯 · 体育赛事编排与成绩管理系统（SportFlow）

一个综合性运动会/联赛的赛事编排与成绩管理平台，支持多项目、多赛制（单循环 / 小组赛+淘汰赛 / 单败淘汰 / 田径计时）编排，参赛队伍与运动员注册、赛程自动排定、比分录入、积分排名、奖牌统计与成绩册输出。适用于校运会、省市级联赛等场景。

> 视觉风格：**明亮运动活力风**（浅色底 + 活力橙/绿茵/天际蓝），与工程内其他项目（深色科技风）刻意区分。

## 技术栈

- **前端**：Vue 3 + Vite + Pinia（状态管理）+ 原生 SVG/条形可视化
- **后端**：Express + Node.js 内置 `node:sqlite`（需 **Node ≥ 22**，低版本可用 `npx -y node@22 server/index.js` 启动后端）
- **数据库**：SQLite（`server/event.db`）
- **通信**：REST API，Vite 代理 `/api` 到后端
- **启动**：`concurrently` 并行拉起前后端（后端 4170 / 前端 5203）

## 数据模型（SQLite 表）

| 表 | 说明 |
|----|------|
| `sports` | 比赛项目（类别 / 赛制 format：roundrobin·group_knockout·knockout·track / 名额 quota） |
| `units` | 参赛单位（学院/俱乐部，含主题色） |
| `teams` | 队伍（归属单位 + 项目 + 状态 status：pending/approved/rejected/withdrawn/revoked） |
| `athletes` | 运动员（田径等单项 + 状态 status） |
| `venues` | 场地 |
| `referees` | 裁判（专长 sport / 等级 level：主裁·助理裁判·记录台，等级向下兼容执法角色） |
| `matches` | 对阵场次（小组/半决赛/决赛/季军，比分、决胜比分、胜方与状态 status：scheduled/finished/void，备注 note 记录弃权/成绩取消原因） |
| `assignments` | 裁判执法安排（场次×裁判×角色 chief/assistant/recorder，status：assigned 在派 / released 已解除；场次-裁判在派唯一索引防重） |
| `assignment_logs` | 排班全量留痕（assign/force_assign/auto_assign/release/reassign/swap/match_change/reschedule_rollback/schedule_added/schedule_rebuild/match_finish/void_release，含原因与操作人） |
| `entries` | 单项成绩（mark + rank） |
| `standings` | 积分榜（赛/胜/平/负/进失/积分/排名，仅统计已通过资格审核的队伍） |
| `medals` | 奖牌榜（金/银/铜） |
| `registrations` | 参赛报名与资格审核（kind：team/athlete，状态流转 pending→approved/rejected，退报 withdrawn / 撤销 revoked，含名额序号 quota_no、审核人与备注） |

## 核心算法

- **单循环**：两两配对生成 `n*(n-1)/2` 场，积分最高者为冠军。
- **小组赛 + 淘汰赛**：分组循环 → 按每组积分排名（胜 3 / 平 1 / 负 0，净胜球次序）→ `A1 vs B2`、`B1 vs A2` 交叉半决赛 → 决赛 + 季军战。
- **单败淘汰**：半决赛 → 胜者晋级决赛、负者争季军。
- **淘汰赛平分决胜**：半决赛/决赛/季军战常规时间战平时，必须录入加时/点球决胜比分（不得再次持平），系统以决胜结果确定胜方并持久化到 `matches.winner`；晋级编排、奖牌结算、对阵展示统一读取该字段，未决胜前不会生成下一轮对阵。决胜比分不计入进失球。
- **田径计时**：成绩升序自动排名，前 3 结算金/银/铜。
- **奖牌统计**：按单位累计各项目冠军/亚军/季军。

淘汰赛对阵不是一次性预排，而是**按当前小组赛/半决赛真实赛果动态生成**——在"赛程编排"页当小组赛（或半决赛）完赛后点击"🧩 编排下一轮淘汰赛"，系统读取实时排名后自动填入对阵。

## 核心流程

**参赛资格审核**（报名审核页）：各单位提交队伍/运动员报名 → 组委会审核资格与名额（通过数不得超过项目名额上限）→ 通过后纳入参赛名单；循环赛项目若尚未开赛则自动重排对阵，把新队伍纳入赛程。退报或资格撤销时**同步处理受影响的对阵及成绩**：未赛场次判弃权（对手 3:0 胜），已赛场次取消成绩并重算积分榜与奖牌；田径项目删除该运动员成绩并重排名。

**审核幂等与事务**：审核（通过/驳回）、退报/撤销均为**幂等操作**——重复提交（双击/重试/并发）返回首次处理结果，不重复占名额、不重复触发赛程重排与级联；名额检查 → 占位 → 资格生效 → 赛程重排 → 积分/奖牌重建整体包裹在 `BEGIN IMMEDIATE` 单事务中（`withTransaction`），并发审核被串行化，任一环节失败整体回滚，杜绝超额参赛与半重排中间态。`POST /api/maintenance/repair` 提供**历史赛程统计修复**（幂等）：循环赛重复对阵去重、已通过报名名额序号重排、失格运动员残留成绩清理、积分榜与奖牌榜按权威赛果全量重建；服务启动时自动执行一次。

**赛事编排**：赛程编排（自动生成对阵）→ 录入比分（成绩录入页）→ 积分榜/排名自动更新 → 完赛阶段动态编排下一轮淘汰赛 → 单项目决出冠亚季 → 汇总至奖牌榜与报表中心。

## 裁判排班与场地协同（整场协同）

在「📍 场地裁判」页提供四个协同视图：

1. **排班总览**：按项目列出全部待赛场次的**整场执法名单（1 主裁 + 助理裁判 + 记录台；五人制足球配 2 名助理）**，可逐场安排、🤖 **一键整场智能排班**——逐场按角色补齐全部空缺席位。顶部统计卡给出**执法席位覆盖率（已排/应排）**与主裁/助理/记录台**分角色覆盖率**，预警条实时汇总名单不齐（空缺席位数）、撞档、跨专长、跨等级。
2. **场地协同**：各场地时段排布同时覆盖待赛与已完赛归档，实时区分待赛撞场和历史重叠；每场显示主裁与「助理/记录台 x/y」就位情况，可就地改期、自动重排或更正历史档案。
3. **裁判名册**：专长/等级/状态 + 已执法/待执法负荷（按 主裁·助理·记录台 拆分），冲突、跨专长、跨等级标记，支持录入新裁判。
4. **变更留痕**：排班、强制覆盖、临时调班（改派/同角色对调，必填原因）、解除、赛程变更、赛程新增/重排、完赛归档、退报取消解除——全部写入 `assignment_logs`，带原因与操作人可追溯。

**整场执法配置（`crewSpec`）**：球类项目每场需 `主裁×1 + 助理裁判×(足球2/其余1) + 记录台×1`；田径无裁判组。覆盖率、缺口与预警统一以"执法席位"为口径统计。

**智能排班算法（`autoFillCrews`）**：按时段升序逐场处理，每场依次补齐 主裁→助理→记录台 缺口；每个席位的候选裁判统一按 **专长精确匹配 → 同类别 → 综合执法 → 跨专长；等级与角色匹配优先（避免高等级裁判被过度占用）→ 待赛负荷低 → 无同时段冲突** 排序择优；已在该场名单中的裁判不重复占位。排班过程中即时感知同轮新增占用，天然完成工作量均衡。

**校验规则**：
- **时间冲突**：同一裁判同一 `time_label` 不得执法两场待赛（任意角色都算占用）；同场地同时段不得排两场。
- **专长**：专长不符默认拦截，填写原因后可**强制安排**并标记预警。
- **等级资质**：等级只能向下兼容（主裁可兼助理/记录台，助理不可当主裁、记录台不可当主裁/助理）；资质不符默认拦截，可强制安排并标记「跨级」。临时调班（改派/同角色对调）同样做专长、等级与冲突预检，对调仅限相同执法角色。

**赛程变更联动整场执法安排**：调整**待赛场次**时间/场地时，系统在单事务中先应用变更、再基于变更后的全局状态检测场地与裁判冲突；默认开启**自动重排**，逐席释放冲突裁判并按专长/等级/负荷自动改派，随后补齐该场主裁/助理/记录台缺口。场地撞场或存在无合格替补的裁判冲突时，整笔改期（场次、排班、自动改派、留痕）**原子回滚**，并补写 `reschedule_rollback` 留痕；仍需强行调整时可选择强制保留冲突并留痕。调整**已完赛场次**时只更正历史时间/场地档案，比分、积分和已归档执法名单不变，且必须填写更正原因；场地视图会区分待赛撞场与历史归档重叠。新生成的淘汰赛/半决赛、循环赛重排的新场次均**自动整场协同排班**（补齐主裁/助理/记录台，无可用裁判的席位留待排班页）；报名通过触发循环赛重排时，旧场次执法安排全部解除并留痕；退报/撤销资格导致的弃权（判 3:0 完赛 → 执法记录归档）与成绩取消（场次 void → 解除在派裁判）均联动；比分录入页与赛程页显示整场名单，录入比分时未派主裁或缺助理/记录台均返回预警；总览页与报表中心展示**已完赛归档 + 待赛排班**合并覆盖率及分待赛/已完赛口径，报表中心同步分角色覆盖率、按角色拆分的执法工作量、场地冲突与最新变更。
